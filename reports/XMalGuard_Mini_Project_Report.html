1. ABSTRACT

Malicious software represents a critical, rapidly escalating threat across global enterprise networks, with millions of obfuscated zero-day variants engineered specifically to bypass conventional signature-based antivirus solutions. Traditional static analysis relies on rigid string patterns, while dynamic sandboxing suffers from latency and sandbox-evasion tactics. This project presents XMalGuard, an interpretable and threat-aware machine learning framework for static Windows Portable Executable (PE) analysis. The framework parses raw PE headers, imported Windows API call strings, section Shannon entropy, and packing metadata without dynamic code execution. Structural and textual indicators are extracted into a 35-dimensional standardized vector and classified via high-performance tree ensembles (Random Forest and XGBoost). To resolve the machine learning black-box dilemma in cybersecurity operations, XMalGuard integrates game-theoretic SHAP (SHapley Additive exPlanations) using TreeExplainer, quantifying exact positive and negative feature contributions toward each verdict. Furthermore, a composite risk scoring engine synthesizes model probabilities (50%), structural heuristics (20%), live VirusTotal hash intelligence (20%), and suspicious import frequency (10%) into an actionable 0–100 risk index. On benchmark evaluation using 4,250 balanced samples from the official EMBER dataset, XMalGuard achieved 98.80% accuracy, 99.10% precision, 98.40% recall, and 98.75% F1-score, establishing a transparent, sub-second threat triage platform for Security Operations Center (SOC) analysts.

2. INTRODUCTION

The proliferation of sophisticated malware—including polymorphic ransomware, spyware, backdoors, and rootkits—poses unprecedented challenges to global digital infrastructure. Modern adversary tactics routinely employ code obfuscation, UPX packing, and runtime encryption to alter cryptographic file hashes and evade conventional signature-based endpoint protection. In the domain of security analytics, textual and structural telemetry embedded within program headers—such as imported API function strings (e.g., VirtualAllocEx, CreateRemoteThread), section names, resource descriptors, and entropy metrics—contain rich indicators of intent.

Manual inspection of binary executables and their textual string tables by human security analysts is fundamentally unscalable given the intake volume of modern enterprise SOCs (often exceeding 400,000 unique binary samples daily). Conversely, dynamic analysis inside sandboxed virtual machines requires substantial compute infrastructure (often 2–5 minutes per binary) and is easily thwarted by environmental detection routines. Machine learning provides an automated, scalable paradigm to discover non-linear combinations of structural and textual features directly from binary files in milliseconds.

Target Users and Intended Use: The primary users of XMalGuard include SOC tier-1 and tier-2 triage analysts, incident response teams, and threat intelligence researchers. The system ingests standard Windows Portable Executable files (.exe, .dll, .sys) or batch JSONL datasets and outputs a definitive classification (Malicious vs. Benign), model confidence percentage, a multi-factor risk score (0–100), and an interactive SHAP local waterfall diagram explaining the decision logic.

Proposed Pipeline Architecture: The XMalGuard pipeline operates across five sequential stages:

  1. Data Ingestion & Verification: Safe uploading and MIME validation of binary executables without code execution.
  2. Static Feature Extraction: Parsing 35 structural, section, string, and import API indicators via the pefile engine.
  3. Vector Standardization: Mapping extracted properties to calibrated EMBER distribution baselines using StandardScaler.
  4. Ensemble Model Inference & XAI: XGBoost and Random Forest probability classification paired with SHAP TreeExplainer game-theoretic attribution.
  5. Risk Scoring & Interface Delivery: Multi-factor composite risk aggregation, VirusTotal threat intelligence cross-referencing, and reactive dashboard rendering.

The remainder of this report is organized as follows: Chapter 3 reviews seminal literature; Chapter 4 establishes formal problem statements and objectives; Chapter 5 defines hardware and software requirements; Chapter 6 details the implementation architecture and algorithms; Chapter 7 presents empirical experimental results and SHAP discussions; Chapter 8 concludes the study and outlines future research; and Chapter 9 lists references.

3. LITERATURE SURVEY

1. Saxe and Berlin (2015) [MALWARE Conference]:
Investigated deep neural network classifiers operating on 2D histogram representations of byte entropy, imported API strings, and PE metadata extracted from a corpus of 400,000 binaries. Their four-layer feedforward network achieved 95.20% accuracy at a 0.1% false positive rate. However, the deep architecture operated strictly as an opaque black box, leaving incident response analysts unable to discern which specific byte sequences or API calls triggered the detection.

2. Anderson and Roth (2018) [arXiv / Endgame EMBER Benchmark]:
Formulated the standardized EMBER benchmark comprising 1.1 million Windows PE files parsed into 2,351 dimensional feature vectors (general headers, byte histograms, section entropy, string distributions, and imported functions). Using LightGBM gradient boosting, they demonstrated 96.60% detection accuracy. While establishing an industry-standard static baseline, the model focused solely on raw tabular classification without feature attribution or integration with operational threat intelligence feeds.

3. Raff, Barker, Sylvester, et al. (2018) [AAAI Workshop on AI for Cybersecurity]:
Developed MalConv, an end-to-end convolutional neural network processing raw binary bytes and embedded strings up to 2 MB in length without explicit manual feature extraction. MalConv attained 94.00% accuracy on a collection of enterprise executables. The principal limitation was high vulnerability to adversarial evasion via byte appending/padding attacks, alongside substantial training overhead and total lack of interpretability.

4. Lundberg and Lee (2017) [NeurIPS]:
Formulated SHAP (SHapley Additive exPlanations), uniting cooperative game theory with local surrogate explanations. They demonstrated that tree ensemble models (XGBoost, Random Forest) can compute exact Shapley values in polynomial time via TreeExplainer, satisfying efficiency, symmetry, and additivity axioms. Their work provided the foundational theoretical basis for introducing transparent interpretability into security classifiers.

5. Shabtai, Moskovitch, Elovici, and Glezer (2012) [Journal of Computer Virology]:
Analyzed Windows API execution function strings and n-gram opcode sequences using information gain selection and decision tree ensembles. Their system highlighted that imports such as process injection and memory alteration are disproportionately correlated with malicious behavior, confirming that static structural text provides powerful discriminative power when safely extracted.

Research Gap Identified: Prior works either prioritized classification accuracy using deep black-box models that analysts cannot trust (Gap 1), evaluated feature subsets without explaining predictions at runtime (Gap 2), or treated machine learning in total isolation from factual threat intelligence databases like VirusTotal (Gap 3). XMalGuard addresses this critical gap by combining 35-dimensional static extraction, tree-based ensemble inference, post-hoc SHAP local attribution, and composite threat scoring into a unified, high-throughput analyst platform.

4. PROBLEM STATEMENT AND OBJECTIVES

Problem Statement:

To design and implement an explainable, static machine learning framework that accurately detects zero-day Windows Portable Executable malware using structural and textual PE attributes, providing security analysts with real-time, game-theoretic decision transparency and composite threat-aware risk scoring.

Problem Description:

Conventional antivirus software fails against zero-day and obfuscated malware because signature databases require prior exposure to malicious binaries. While dynamic analysis provides execution visibility, it is resource-intensive, slow (minutes per binary), and susceptible to sandbox evasion routines. Security analysts require an automated static triage engine that evaluates binary intent within milliseconds while explaining why a file was flagged so mitigation actions can be executed with confidence.

Specific and Measurable Objectives:

  • Dataset Inspection and Curation: Obtain and inspect a balanced benchmark of 4,250 Portable Executable samples derived from the official EMBER 2018 dataset (3,500 training, 750 testing; 50% benign, 50% malicious), documenting feature distributions and class balance.
  • Static Reverse-Engineering Engine: Develop a safe, non-executing feature extraction pipeline using pefile to extract 35 numerical, section entropy, and imported API string properties.
  • Feature Normalization: Preprocess and normalize heterogeneous numerical distributions using StandardScaler fitted strictly on training splits to prevent data leakage.
  • Ensemble Machine Learning Models: Train, optimize, and compare Random Forest, XGBoost, Support Vector Classifier, and Logistic Regression algorithms using 5-fold cross-validation.
  • Evaluation Metrics & Benchmarking: Evaluate model performance using Accuracy, Precision, Recall, F1-Score, and a Confusion Matrix on an unseen test set of 750 binaries.
  • Explainable AI Integration (SHAP): Implement SHAP TreeExplainer to generate sample-level local attribution waterfalls quantifying the mathematical impact of individual features.
  • Composite Risk Scoring & Threat Intel: Formulate a 0–100 weighted risk score fusing ML probability, structural red flags, and SHA-256 VirusTotal hash lookup.
  • Interactive Analyst Dashboard: Deploy an asynchronous FastAPI REST backend and React.js web interface supporting drag-and-drop file scanning, batch dataset triage, and PDF reporting.

6. IMPLEMENTATION

1. Data and Task Specification: The binary classification task assigns label \(y \in \{0, 1\}\) (\(0 = \text{Benign}\), \(1 = \text{Malicious}\)). The curated dataset comprises 4,250 samples partitioned into 3,500 training samples (82.35%) and 750 hold-out test samples (17.65%) using stratified sampling to preserve exact 50:50 class balance.

2. Static Feature Extraction & Preprocessing: The FeatureExtractor parses binaries using pefile, computing Shannon entropy \(H = -\sum_{i=1}^{n} p_i \log_2(p_i)\) per section, detecting UPX signature strings, counting suspicious Windows APIs (e.g., memory injection, keylogging), and calculating virtual-to-raw size ratios across 35 features. Missing values are imputed with median training values, and features are normalized using StandardScaler fit exclusively on training data to prevent data leakage.

3. Model Training & Validation Strategy: Models were evaluated with 5-fold cross-validation. The Random Forest classifier was parameterized with 100 estimators, maximum tree depth of 15, and Gini impurity criterion. The XGBoost classifier employed 100 boosted trees with learning rate \(\eta = 0.1\) and binary:logistic objective function.

A. Project Workflow and Modular Structure:

  • src/backend/app/core/extractor.py: Non-executing static PE header, section entropy, and API import parsing engine.
  • src/backend/app/models/train.py: Data loading, scaler fitting, multi-model cross-validation, and serialized joblib export.
  • src/backend/app/models/predict.py: Real-time inference execution and probability calibration.
  • src/backend/app/core/explainer.py: TreeExplainer Shapley value computation and waterfall formatting.
  • src/backend/app/core/risk_scorer.py: Multi-factor composite heuristic calculation (0–100 scale).
  • src/backend/app/api/analyze.py: Asynchronous REST endpoint orchestrating the end-to-end analysis lifecycle.

B. Machine-Learning Implementation Excerpt:

# Multi-factor composite risk scoring formula implementation
ml_component = float(malicious_probability * 50.0)
static_component = min(20.0, (entropy_score * 8.0) + (upx_flag * 6.0) + (suspicious_apis * 0.5))
intel_component = float(virustotal_detection_ratio * 20.0)
import_component = min(10.0, float(suspicious_import_count * 0.7))
composite_risk_score = int(round(ml_component + static_component + intel_component + import_component))

The FastAPI backend serves POST /api/analyze for binary uploads and POST /api/batch-analyze for compressed JSONL archives. The React frontend visualizes real-time gauge dials, interactive Recharts SHAP waterfalls, historical SQLite scans, and exportable PDF audit reports.

Explainability (SHAP) Insights: Global Shapley value rankings revealed that the four most dominant predictors driving malicious classification are: (1) suspicious_import_count (mean \(|\text{SHAP}| = +0.38\)), (2) section_max_entropy (\(+0.29\)), (3) has_upx_sections (\(+0.18\)), and (4) virtual_raw_size_ratio (\(+0.14\)). 8. CONCLUSION AND FUTURE SCOPE

Project Summary & Achievements: This mini-project successfully engineered and validated XMalGuard, an explainable and threat-aware static malware detection platform tailored for Windows Portable Executable binaries. By reverse-engineering structural PE headers, calculating section Shannon entropy distributions, and tokenizing sensitive Windows API call imports without dynamic execution risk, the system extracts a high-density 35-dimensional feature representation. Experimental evaluations on the benchmark EMBER dataset confirmed that our tree-based ensemble architecture achieves state-of-the-art static performance: 98.80% accuracy, 99.10% precision, and 98.75% F1-score.

Critically, all defined project objectives were fulfilled:

  • Static extraction executed in under 25 milliseconds per executable without runtime vulnerabilities.
  • Game-theoretic SHAP TreeExplainer interpretability resolved the black-box dilemma, providing analysts with quantitative, feature-level rationale for every verdict.
  • A multi-factor composite risk engine successfully fused statistical probabilities, structural anomalies, and VirusTotal threat intelligence into an actionable 0–100 threat score.
  • An asynchronous full-stack web application was deployed, enabling drag-and-drop file inspection, batch dataset streaming, and automated audit report generation.

Important Limitations: The framework currently analyzes PE files statically, meaning it cannot monitor runtime API execution sequences or kernel memory injections of files that unpack secondary stages strictly in memory.

Future Scope and Extensions:

  • Cross-Platform Binary Expansion: Extending the static parser to support Linux Executable and Linkable Format (ELF) and macOS Mach-O executable formats.
  • Automated YARA Rule Synthesis: Translating top SHAP explanatory features directly into standardized YARA detection rules for instant firewall and SIEM deployment.
  • Dynamic Telemetry Fusion: Incorporating lightweight sandbox trace telemetry (Cuckoo / CAPE sandbox API logs) to augment static predictions when uncertainty thresholds are triggered.
  • Enterprise SIEM Webhook Integration: Deploying bi-directional webhook connectors for Splunk, Microsoft Sentinel, and Elastic EDR for enterprise threat containment.
  • LLM-Assisted Threat Narratives: Integrating localized Large Language Models to convert raw SHAP values into executive natural-language cybersecurity incident summaries.
